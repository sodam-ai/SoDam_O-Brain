## 1. 디자인 시스템 & 재사용 (결정)

현재 코드에 기존 디자인 시스템이 **없으므로**, 아래를 표준으로 채택해 처음부터 재사용 가능하게 둔다.

> **[확인됨, 2026-08-03 갱신] React 미사용 확정에 따라 Tailwind·shadcn/ui는 채택하지 않음** — 아래 표는
> 실제 구현(순수 CSS + 디자인 토큰 + 직접 구현한 접근성)으로 동기화. **원안이 요구한 원칙(접근성 내장·
> 토큰 일관성·과장식 없음)은 전부 그대로 유지**하고, 구현 수단만 프레임워크 없는 방식으로 바뀜.

| 항목 | 채택 | 이유 |
|------|------|------|
| 스타일 | ~~Tailwind CSS~~ → **순수 CSS + CSS 변수 토큰** | 일관된 간격·색·타이포를 토큰으로 강제(목적 동일), 빌드도구 없는 구조와 일치 |
| 컴포넌트 | ~~shadcn/ui (Radix 기반)~~ → **직접 구현 컴포넌트**(키보드 핸들러·ARIA 속성 수동 부여) | 접근성 내장 목표는 동일 유지, 복붙 재사용 대신 단일 HTML 내 함수로 재사용 |
| 디자인 토큰 | CSS 변수(`--bg`·`--surface`·`--text`·`--accent`·분류색) | 라이트/다크 한 곳에서 전환 — [확인됨] 실제 구현과 일치, 변경 없음 |
| 아이콘 | ~~lucide(shadcn 기본)~~ → **인라인 SVG/유니코드 기호**(직접 배치) | 단정한 라인 아이콘 유지, 별도 아이콘 패키지 의존 없이 구현 |

> 원칙(유지): **새 UI는 디자인 토큰을 우선 재사용**한다(원안의 "shadcn/ui 컴포넌트 우선 재사용"에서
> 구현 수단만 교체, "토큰을 벗어나지 않게"라는 취지는 그대로). 커스텀은 토큰을 벗어나지 않게.

## 10. 타이포그래피 · 여백 · 정렬 · 대비

- **타이포 스케일**: 12 / 14(본문 기본) / 16 / 20 / 24px, 줄간격 1.5. 본문 시스템 폰트, 경로·코드·임베딩값은 모노스페이스.
- **위계**: 화면당 제목(20~24) 1개, 섹션(16), 본문(14), 보조(12·muted). 굵기는 400/500/600만.
- **여백(8pt 그리드)**: 간격은 4·8·12·16·24·32px만 사용. 카드 패딩 16, 섹션 간 24.
- **정렬**: 좌측 정렬 기본, 숫자(중요도·날짜)는 우측 정렬. 라벨·값 수직 정렬 일관.
- **대비**: 본문 텍스트 대비 **WCAG AA 4.5:1 이상**, 보조 텍스트도 3:1 이상. 회색 위 회색 금지.

## 11. 핵심 UI 요소 (CTA · 버튼 · 폼 · 카드 · 메뉴)

- **CTA/버튼**(~~shadcn Button~~ → 직접 구현 `<button>` + 토큰 스타일): 화면당 **주 버튼(Primary) 1개**만 강조, 나머지는 secondary/ghost. 파괴적 동작(삭제·병합)은 **destructive(빨강) + 확인 모달**.
- **폼(설정·검색·편집)**: 라벨 항상 표시(placeholder로 대체 금지), 인라인 검증·도움말, 키 입력은 `password` 타입 + 표시 토글. 저장 시 토스트 피드백.
- **카드(기억)**: 평면 카드(테두리 1px, 그림자 최소). 제목·유형 뱃지·중요도·발췌 2줄. 호버 시 미세한 배경 변화만.
- **메뉴/드롭다운**(~~shadcn~~ → 직접 구현 `<select>`/커스텀 드롭다운): 프로젝트 선택·정렬·필터. 키보드 탐색 가능. 항목 7±2개 넘으면 검색 포함.
- **뱃지**: 유형/분류는 색+텍스트(색만으로 의미 전달 금지).

## 12. 반응형 · 모바일 UX · 터치

기준 폭: **모바일 375px / 태블릿 768px / 데스크톱 1024px+**.

- **데스크톱(1024+)**: 3분할(필터·캔버스·상세).
- **태블릿(768)**: 상세 패널 → 슬라이드 오버레이, 필터 → 접이식.
- **모바일(375)**: 단일 컬럼. 필터 → **햄버거/바텀시트**, 상세 → 전체화면 시트, 상단 검색 고정.
  - **그래프 3D는 모바일에서 기본 비활성(2D만)** — 성능·조작성 한계. 목록/검색/상세/타임라인은 완전 사용 가능.
- **터치 영역**: 모든 탭 대상 **최소 44×44px**, 간격 8px 이상(오터치 방지).
- **정보 우선순위(작은 화면)**: 검색 > 목록/그래프 > 필터 > 부가정보 순으로 노출.

## 13. 상태 피드백 (모든 인터랙션 요소)

| 상태 | 처리 |
|------|------|
| hover | 미세한 배경/테두리 변화 (이동·확대 금지) |
| focus | **항상 보이는 포커스 링**(키보드 접근성, 제거 금지) |
| active | 눌림 표현(살짝 어둡게) |
| disabled | 흐림 + 커서 not-allowed + 이유 툴팁 |
| loading | **스켈레톤/스피너** + "AI 호출 중" 등 무엇을 기다리는지 표시 |
| empty | 안내문 + 다음 행동 버튼 (막막함 방지) |
| error | 친절한 한국어 메시지 + 재시도. 원문 오류는 접어두기 |
| success | 토스트(2~3초) — 과한 축하 연출 X |
| warning | 비가역 동작 전 확인(삭제·병합·내보내기 덮어쓰기) |

> 원칙: 모든 실패·대기 상태를 **반드시 가시화**(05 §3 silent-failure 금지와 연결).

## 14. 접근성 (Accessibility)

- 키보드만으로 전 기능 사용(탭 순서 논리적, 포커스 트랩은 모달에서만).
- 색에만 의존 금지 — 의미는 **색 + 아이콘/텍스트** 병행(모순=빨강+┄아이콘).
- 대비 AA 준수, 모션 민감 사용자 위해 `prefers-reduced-motion` 존중(애니 최소·끌 수 있음).
- ~~shadcn/ui(Radix) 기본 ARIA 활용~~ → **직접 부여한 ARIA 속성**(role·aria-label 등 수동 구현, Radix 미사용), 이미지/아이콘 대체텍스트.

## 16. UI/UX 우선순위 (MoSCoW)

**Must (P1 필수)**
- 디자인 토큰·라이트/다크, 대비 AA, 키보드 네비·포커스 링
- 터치 ≥44px, 반응형(필터→햄버거, 상세→시트)
- 8가지 상태 피드백 전부, 빈/에러 상태 안내
- ~~shadcn/ui 기본 컴포넌트 재사용~~ → **직접 구현 컴포넌트 + 디자인 토큰 재사용**(2026-08-03 갱신), 그래프 기능색(분류·모순·강조)

**Should (P1~P2)**
- 라이트/다크 토글, 검색어 하이라이트, 스켈레톤 로딩
- 타임라인 변천선, 로컬/글로벌 전환의 절제된 트랜지션

**Could (P2~P3)**
- 3D 카메라 프리셋, 키보드 단축키 팔레트, 테마 커스터마이즈
