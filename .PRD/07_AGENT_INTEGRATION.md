# O-Brain — AI 연동 (기억 되읽기·재활용)

> 07 — 01~06은 기억을 "저장(write)"하는 쪽이었고, 이 문서는 AI가 그 기억을 "읽어 쓰는(read)" 쪽.
> 누락 보완: 기억은 AI가 다음 세션에서 못 꺼내 쓰면 의미 없음 → 이 연결이 빠지면 제품 가치가 0.
> 생성일: 2026-06-20 (v6 — AI 연동/되읽기 추가)

---

## 1. 핵심 문제

저장만 잘 되고 **되읽기(retrieval)** 설계가 없으면, 클로드코드는 어제 저장한 결정을 내일도 모른다. 저장과 되읽기는 한 쌍이어야 한다.

> 근거(확인됨): claude-mem은 mem-search 스킬 + 4개 MCP 도구로 "3단계 점진 공개"로 되읽고, memory-bank는 9개 MCP 도구(search·trace_fact·explore_graph 등)를 제공한다. 즉 경쟁 도구 모두 **되읽기 인터페이스**를 핵심으로 둔다.

---

## 2. 두 가지 되읽기 경로

### (A) 자동 컨텍스트 주입 — SessionStart 훅 (기본·P1)
- 새 클로드코드 세션이 **시작될 때**, 현재 프로젝트의 관련 기억 **상위 N개(소량)**를 자동으로 AI에 주입.
- 주입은 **요약·소량**만 → 토큰 절약. 사용자가 매번 설명할 필요 없음.

### (B) MCP 도구 — AI가 필요할 때 직접 호출 (P1 일부 + P2 전체)
- AI가 작업 중 "예전에 뭐라고 정했지?"가 필요하면 직접 검색.

---

## 3. MCP 도구 목록 (우리 버전)

| 도구 | 하는 일 | Phase |
|------|---------|-------|
| `search_memory(query)` | 의미+키워드 하이브리드 검색, **소량 반환** | P1 |
| `get_memory(id)` | 한 기억의 전체 내용·연결 | P1 |
| `get_related(id)` | 그 기억과 연결된 이웃(1~2 hop) | P2 |
| `get_timeline(topic)` | 한 주제의 변천사(대체·모순) | P2 |
| `list_categories()` | 분류(온톨로지) 목록·개수 | P2 |

> claude-mem(4툴)·memory-bank(9툴)을 참고하되, 1인·로컬에 맞게 **꼭 필요한 5개**로 압축(확인됨).

---

## 4. 토큰 절약 원칙 (3단계 점진 공개)

> 근거: claude-mem의 "3-layer progressive disclosure"(확인됨).

1. **1단계**: 제목·유형·중요도만 (목록).
2. **2단계**: 사용자가/AI가 고른 것만 내용 펼침.
3. **3단계**: 필요 시 연결·이력까지.

→ 한 번에 전부 안 줌. 컨텍스트(토큰) 폭주 방지.

---

## 5. 자동 주입 랭킹 규칙

주입할 상위 N개를 고르는 가중치:
- **scope**: 현재 프로젝트(project) 우선 + 전역(global) 보조.
- **관련성**: 현재 작업/프롬프트와의 의미 유사도(임베딩).
- **합성 점수(예시 공식)**: `의미유사도 × 0.7 + 중요도 × 0.15 + 최근성 × 0.1 + 신뢰도 × 0.05` → 관련성 우선, **신뢰도 낮은(오추출 의심) 기억은 후순위**. (근거: claude-knowledge-graph 가중식 `sim×0.7+imp×0.2+rec×0.1` + Memento confidence — 정독 확인)
- **신뢰도 감쇠(Phase 2)**: 강화 안 된 오래된 기억은 신뢰도가 서서히 낮아져 순위 하락(삭제 X). (근거: Memento 반감기 감쇠, 기본 30일)
- **유효성**: `valid_until`이 지난(대체된) 기억은 기본 제외(단, 시간여행 요청 시 포함).

---

## 6. 코덱스 연동

- 코덱스가 MCP를 지원하면 **같은 5개 도구** 그대로 사용.
- 미지원이면(가능성, 미확인) → 세션 시작 시 **컨텍스트 파일 주입 폴백**(관련 기억을 임시 파일로 넘김). 02·03의 "세션 로그 파일 폴백"과 같은 안전망 철학.

---

## 7. 보안 (되읽기 단계)

- 주입·반환되는 기억에는 **이미 시크릿이 없다**(저장 단계 05 §2에서 제거됨). 되읽기에서 키가 새어나갈 일 없음.
- 자동 주입이 일어나면 "이번 세션에 기억 N개 참고함"을 사용자에게 표시(은폐 금지).

---

## 8. Phase 배치

| Phase | 되읽기 기능 |
|-------|------------|
| **P1** | SessionStart 자동 주입(소량·요약) + `search_memory`·`get_memory` |
| **P2** | `get_related`·`get_timeline`·`list_categories` + RAG 자동 첨부 + 3단계 점진 공개 강화 |
| **P3** | 코덱스/멀티도구 MCP 통합, 주입 랭킹 정교화 |

---

## 9. 확정 / 원칙

- **확정**: P1은 "자동 주입 + 검색 2종"으로 최소 되읽기를 보장(저장만 하고 못 읽는 반쪽 제품 방지).
- **원래 목적 유지**: 클로드코드·코덱스가 과거 맥락을 자동으로 되찾게 하는 것이 이 제품의 존재 이유 — 이 문서가 그 마지막 고리.
