# O-Brain — 보안 요구사항 (핵심)

> 08 — 보안은 **선택이 아니라 핵심 요구사항**. 기준: **OWASP ASVS Level 1 + Secure by Design**.
> 생성일: 2026-06-20 (v8 — 보안 요구사항 보강)
> 맥락 전제(중요): O-Brain는 **100% 로컬 · 1인 · 무로그인 · 무서버(localhost) · Supabase 미사용**.
> → 일반 웹앱 항목 중 일부는 **그대로는 해당 없음(N/A)**. 억지 적용 대신 실제 구조에 맞게 적용하고, 미해당은 이유와 함께 표시한다.

## 0. 보안 원칙

- **Secure by Design**: 기능보다 먼저 안전. 기본값이 가장 안전한 상태(secure default).
- **불신 전제**: 모든 입력(훅 페이로드·검색어·URL 파라미터·폼·API 요청·파일 경로)은 **신뢰하지 않는다**.
- **최소 노출**: 데이터·서버·권한을 필요한 최소로. 로컬 밖으로 절대 새지 않게.

## 1. 위협 모델 (O-Brain 특유 — 가장 중요)

| 위협 | 설명 | 핵심 대응 |
|------|------|-----------|
| **로컬 웹서버 노출** | localhost 서버가 같은 네트워크/타 프로세스에 열리면 내 기억 유출 | **127.0.0.1 전용 바인딩** (0.0.0.0 금지) |

## 2. 인증 · 인가 · 접근 통제 (ASVS V1/V2/V4)

- **로그인 없음**: 내 PC 1인 전용이라 사용자 인증 미도입(의도된 결정).
- 대신 **로컬 접근 통제**로 대체(Must):
  - 서버는 **`127.0.0.1`(루프백)에만 바인딩** — 외부 기기 접근 차단.
  - **CORS**: `Origin`을 localhost(자기 자신)만 허용. 그 외 거부.
  - **Host 헤더 허용목록** [구현, 2026-10-20]: 허용한 Host(`127.0.0.1`·`localhost` + 서버 포트) 외에는 첫 화면(토큰이 박힌 HTML)·API·정적 파일 모두 403 — 악성 웹페이지가 도메인을 127.0.0.1로 되돌려 서버를 읽는 **DNS 리바인딩**을 막는다. 격리 서버 요청 매트릭스 12건으로 확인(나쁜 Host·Host 없음·틀린 포트 거부 / 정상 접속·기존 방어 회귀 없음).
  - (Should) **로컬 API 토큰**: 웹↔로컬서버 간 무작위 토큰 1개를 부팅 시 생성해 헤더로 검증(타 프로세스 무단 호출 차단).
- **권한 분리(관리자/일반/비로그인)**: **N/A** — 단일 사용자·단일 권한. (향후 팀/클라우드 도입 시 조건부: §9 참조)

> 수용 기준: `netstat`에서 서버 포트가 **127.0.0.1만 LISTEN**(0.0.0.0 아님). 외부 IP로 접속 시 거부.

## 3. 입력값 검증 (불신 전제 · ASVS V5)

검증 대상과 기준:
- **훅 페이로드(JSON)**: 스키마 검증(타입·길이·필수). 파싱 실패 시 안전 폴백.
- **검색어/필터/URL 파라미터**: 길이·타입·허용값 화이트리스트. 과도한 입력 거부.
- **API 요청 바디**: 서버에서 재검증(클라 검증 신뢰 X).
- **파일 경로(데이터 폴더·코덱스 로그·내보내기)**: 정규화 후 **허용 루트 내부만**, `..`·심볼릭 탈출 거부.

> 수용 기준: 잘못된 타입·초과 길이·경로 탈출 입력에 대해 **저장/실행 없이 안전 거부 + 친절 메시지**.

- **[추가·검증, 2026-10-21] id 타입 검증(타입 혼동 방어)**: 요청 본문의 id를 `Number()`로만 바꾸면 `true→1`, `[5]→5`, `''→0`처럼 엉뚱한 값이 id가 된다. 실제로 `POST /api/memory/batch-delete`에 `{"ids":[…, true]}`를 보내면 **기억 #1이 지워지는 결함**을 최종 점검에서 재현했다. `store.mjs`의 `strictId()`(양의 정수 또는 숫자만 든 문자열만 인정, 그 밖에는 `null`)로 `batch-delete`·`duplicates/merge`·`addRelation`·`undoImport`를 고쳤고, `selftest` 46번대 3건이 회귀를 막는다.

## 7. 보안 설정 (ASVS V14)

- **CORS**: localhost 자기 출처만 허용, credentials 최소.
- **쿠키**: 쿠키 미사용이 기본. 부득이 사용 시 `HttpOnly`·`SameSite=Strict`·`Secure`(로컬은 localhost 한정).
- **보안 헤더**: `Content-Security-Policy: default-src 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`.
- **환경 변수**: 설정은 `.env.local`. 코드 하드코딩 금지.
- **디버그/운영 분리**: 운영(기본)에서 **스택트레이스·상세 에러 비노출**(사용자엔 친절 메시지, 상세는 로컬 로그만). dev 모드에서만 상세.
- **[추가·검증, 2026-10-21 최종 점검]** 서버 정보 노출 최소화: `X-Powered-By: Express` 헤더 제거(이전엔 모든 응답에 노출) · 토큰이 박힌 `/`와 모든 `/api/*` 응답에 `Cache-Control: no-store`(기억 내용·토큰이 브라우저/중간 캐시에 남지 않게; 정적 라이브러리 파일은 캐시 유지).
- **[추가·검증, 2026-10-21] 보안 로그(ASVS V7)**: 거절된 요청(허용되지 않은 Host·Origin, 토큰 없음·불일치)을 서버 로그에 `[security] 요청 거절(이유) 메서드 경로 — 최근 N회`로 남긴다. **토큰·헤더 값·쿼리·본문은 절대 기록하지 않으며**, 서버 재시작 뒤 열려 있던 옛 화면의 반복 요청으로 로그가 넘치지 않도록 같은 이유는 **분당 1줄**로 줄인다(실측: 토큰 불일치 수십 건 → 1줄). 기억 삭제·병합·가져오기 같은 파괴적 동작은 별도 감사 로그 대신 **실행 직전 자동 백업**(07 §백업)이 복구 근거가 된다 — 별도 감사 로그는 구현하지 않았다(한계).
- **[추가·검증, 2026-10-21] 서버 재시작 후 옛 화면**: 서버는 실행마다 토큰을 새로 만들므로(위 §6) 이미 열려 있던 대시보드 탭은 계속 403을 받는다. 이전엔 이 상태가 **조용한 먹통**(자동 새로고침은 "변화 없음"으로, 저장·삭제는 "허용되지 않은 요청"이라는 알 수 없는 문구)이었다. 이제 토큰 오류 403을 만나면 화면 위쪽에 "서버가 다시 시작된 것 같아요 — 화면 새로고침" 안내 배너를 띄운다(실브라우저로 재현·복구 확인).
