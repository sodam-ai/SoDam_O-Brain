## 3. 에러 처리·실패 모드 (silent failure 금지)

| 실패 상황 | 동작(fail-safe) | 사용자 표시 |
|------|------|------|
| AI 추출 실패/타임아웃 | `rule` 폴백 자동 전환 | "AI 추출 실패 → 규칙 기반으로 저장함" |
| 훅 신호 누락(코덱스 등) | 세션 로그 파일 폴백 | 조용히 폴백 + 로그 기록 |
| 임베딩 생성 실패 | 키워드(FTS5) 검색만 일시 동작 | "의미검색 일시 중단" 배너 |
| sqlite-vec 로드 실패 | 키워드 검색 유지 + 경고 | 확장 설치 안내 |
| DB 손상 | 읽기 전용 + 백업 복구 권유 | 경고 |

> 원칙: 실패해도 fail-safe로 우회하되, **반드시 사용자에게 가시화**(은폐 금지). `--force`/무시 같은 은폐성 우회 금지.

## 7. 성공지표 (KPI)

- **자동 저장률**: 세션당 유의미 기억 ≥ 1건
- **검색 적중**: 찾던 기억이 상위 5개 안에 (체감)
- **재사용**: 주 1회 이상 그래프·검색 실제 사용
- **시크릿 누출**: **0건**

> **2026-08-10 실측 검증** — 실DB(1,661건, session 1,381건) 읽기 전용 조회로 4개 중 2개를 처음 실측.
> 목표를 달성했다고 포장하지 않고 실측치를 그대로 남긴다(안티패턴: 데이터 없는 낙관 금지).
>
> - **자동 저장률 — 미달성, 가설 1개 기각**: "84.8% 무기억은 O-Brain과 무관한 다른 프로젝트 세션이
>   섞여서"라는 기존 가설을 검증하려고 O-Brain 자체 세션만 따로 뽑아봤다. 결과: O-Brain 세션(31개) 중
>   기억 ≥1건 저장된 것은 9개(**29.0%**) — 기타 프로젝트 세션(1,350개 중 432개, 32.0%)과 **거의 같음**.
>   즉 "관계없는 프로젝트라서 낮다"는 가설은 **기각**됐다 — O-Brain 본인 작업 세션조차 71%가 기억
>   0건이다. 원인은 크로스프로젝트 혼입이 아니라, **규칙기반 추출(ruleExtract)의 리콜(recall) 자체가
>   낮을 가능성**이 유력해 보인다(가능성 — 코드 재감사로 별도 확인 필요, 이번엔 미실행).
>
> **2026-08-10 후속 — 리콜 재감사 완료(코드 수정 1건 + CUES 확장은 보류, 근거 명시)**: 위 "코드
> 재감사"를 실제로 했다. 실제 로컬 transcript(84개 프로젝트 다양성 확보, 프로젝트당 최대 12개,
> 자동화 에이전트 로그 폴더 1곳은 표본이 아니라 판단해 제외 — 최초 시도에서 그 폴더가 표본의 94%를
> 차지해 수치를 왜곡한 것을 발견하고 재표집) 200개를 실제 파이프라인(parseTranscript→redact→
> stripInjected→ruleExtract, DB 쓰기 없이 시뮬레이션)에 통과시켜 재측정: **0건 세션 46.5%**(93/200)
> — 어제 DB 기준 71%보다 낮다(표본 크기 차이: 어제는 O-Brain 세션 31개뿐이라 표준오차가 컸을 가능성 —
> 어느 쪽이 "더 맞다"고 단정하지 않고 방법론 차이를 병기).
> - CUES에 안 걸린 후보 문장 120건(중복제거)을 전부 직접 읽어 분류: **대다수(약 90%+)는 파일경로
>   조각·세션요약 템플릿 헤더(영어)·Codex 자동리뷰 프롬프트/diff 조각**으로, 애초에 기억으로 남으면
>   안 되는 것들이었다(파이프라인이 올바르게 걸러낸 것 — 결함 아님). **CUES 확장으로 건질 만한 명백한
>   사례는 1건**뿐("상담/인터뷰 등은 구현 끝나고 한다니깐 왜 계속 물어보냐"는 사용자의 실제 불만/제약
>   발화). **결론: 이 표본 근거로는 CUES를 넓히지 않는다** — 득(리콜 소폭 상승)보다 실(오탐·노이즈
>   증가) 위험이 크다는 게 실측으로 확인됐다. 무기억 세션 대다수는 결함이 아니라 "애초에 저장할
>   결정이 없던 세션"으로 보는 게 데이터에 더 부합한다.
> - **별도로 발견·수정한 실제 결함(커밋 예정)**: `stripInjected()`가 `<command-...>` 래퍼는 거르면서
>   `<local-command-stdout>`/`<local-command-caveat>` 태그(로컬 `!명령` 실행 결과 래퍼)는 안 거르고
>   있었다. CUES에 안 걸려 저장까진 안 됐지만(실피해 0건), 태그 원문이 close-miss 후보에 계속 섞여
>   나와 방어선이 완전하지 않았음을 확인 — 동일한 패턴으로 제거 추가, 격리 회귀 3종(태그 제거·빈
>   결과·일반텍스트 보존) + selftest 3/3 전부 통과.
> - **재사용 — 미달성**: `access_count>0`(대시보드에서 실제로 열람된 기억)이 1,661건 중 29건(1.7%),
>   최근 7일 내 열람 **0건**, 최근 30일 내 5건, 가장 최근 열람은 2026-07-17(3주 이상 정체). "주 1회
>   이상" 목표에 명백히 못 미친다. 단, 이 지표는 **사용자가 대시보드를 수동으로 열어 노드를 클릭하는
>   행위만 센다** — O-Brain의 핵심 가치 흐름(SessionStart 훅이 다음 대화에 기억을 자동 주입, `hook-
>   prompt.mjs`)은 대시보드를 전혀 안 열어도 작동하므로, **이 지표가 애초에 핵심 사용 경로를 측정하고
>   있는 게 맞는지 자체가 의문**이다(가능성 — 지표 재설계는 사용자 판단이 필요한 사항이라 임의로 기준을
>   낮추거나 재정의하지 않고 여기까지만 정리).
> - **검색 적중**: 체감·정성 지표라 자동 계측 불가, 실측 미실행.
> - **시크릿 누출**: 코드 경로(redact.mjs) 검토 + 격리 XSS/보안배터리로 간접 검증됨(2026-08-09).
>   실제 프로덕션 장기 사용에서 "0건"까지 실측하는 건 미실행.

## 9. 용어집 (비개발자용)

- **훅(hook)**: AI 도구가 특정 순간(세션 종료 등)에 자동으로 부르는 "알림 트리거".
- **임베딩(embedding)**: 문장을 숫자 좌표로 바꿔 "의미가 비슷한지" 재는 기술.
- **온톨로지(ontology)**: 지식을 주제·관계로 분류하는 체계.
- **FTS5**: SQLite의 빠른 키워드 검색 기능.
- **sqlite-vec**: SQLite에서 의미(벡터) 검색을 하는 확장.
- **RRF**: 키워드+의미 검색 결과를 똑똑하게 합치는 방법.
- **노드/엣지**: 그래프의 점(기억) / 선(관계).
