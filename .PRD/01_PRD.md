## 1. 제품 개요

### 한 줄 요약
클로드코드·코덱스 같은 AI 코딩 도구의 대화에서 **중요한 결정·선호·패턴을 자동으로 기억**하고, 그 기억들을 **지식그래프로 연결해 풍부하게 시각화·탐색·검색**하는 **100% 로컬(내 PC) 1인용** 도구.

### 해결하는 문제
- AI 코딩 도구는 세션(대화)이 끝나면 **맥락이 휘발**된다. 어제 "포트는 1601 쓰기로 했지"라고 정했어도 내일 AI는 모른다.
- 매번 같은 설명을 반복하거나, 과거 결정을 사람이 직접 찾아 다시 알려줘야 한다.
- 기존 메모리 도구 대부분은 기억을 **목록(리스트)** 으로만 쌓아, "이 결정이 저 결정을 왜 대체했는지" 같은 **관계·맥락·시간 흐름**이 보이지 않는다.

### 핵심 가치 (이 도구만의 차별점)
> **"기억을 쌓는" 도구가 아니라 "기억을 잇고, 보여주는" 도구.**

1. **풍부한 지식그래프 시각화 (핵심)** — 기억끼리 `영향줌·뒷받침·대체함·모순됨` 관계로 연결하고, **2D/3D 그래프 + 타임라인**으로 군집·진화·모순을 한눈에. (경쟁 도구 대부분은 검색·목록 위주이거나 시각화가 빈약)
2. **온톨로지·관계 중심** — 단순 목록이 아니라 분류(온톨로지)와 타입 관계로 지식을 구조화.
3. **100% 로컬·무의존** — 모든 저장·검색·그래프가 내 PC 안 SQLite 한 곳에서 끝남. 외부 서버·클라우드 계정 불필요.
4. **자동 + 보기 좋은** — AI가 알아서 기억을 뽑아 저장하고(손 안 댐), 나는 화면에서 보고 탐색만.

> 근거(확인됨): [memory-bank](https://github.com/jung-wan-kim/memory-bank)는 온톨로지 + 타입 관계(INFLUENCES/SUPPORTS/SUPERSEDES/CONTRADICTS) + 3D 그래프, [agentmemory](https://github.com/rohitg00/agentmemory)는 외부 의존성 0(순수 SQLite) + 시크릿 제거 필터, [claude-mem](https://github.com/thedotmack/claude-mem)은 세션 훅 5종 + 토큰 절약형 검색, [Graphiti](https://github.com/getzep/graphiti)·[Memento](https://github.com/gannonh/memento-mcp)는 시간여행·진화 추적, [buildautomata 3D viz](https://glama.ai/mcp/servers/@brucepro/buildautomata_memory_mcp)·[TheSethRose Memory-KG-3D](https://github.com/TheSethRose/Memory-Knowledge-Graph-3D)는 Force Graph 기반 3D 시각화를 갖췄다. O-Brain는 이 장점들을 **로컬·1인·시각화 중심**으로 합치고, 관리형 서버에 의존하는 [Revka](https://github.com/KumihoIO/Revka)·[Cognee](https://github.com/topoteretes/cognee)(Neo4j)는 "로컬 전용" 목적과 어긋나 구조를 채택하지 않는다.

## 2. 사용자

### 주요 사용자
- **누구**: 클로드코드·코덱스로 바이브코딩(자연어로 시키는 코딩)을 하는 **본인 1인** (비개발자 포함).
- **상황**: 여러 프로젝트를 오가며 AI와 작업할 때. 과거 결정·규칙·취향을 AI가 기억하고, 나는 그 맥락을 시각적으로 되짚고 싶을 때.
- **목표**: 반복 설명을 줄이고, 과거 맥락(무엇을·왜·언제 결정했는지)을 그래프로 빠르게 되찾기.

### 사용자 시나리오
1. 사용자가 클로드코드로 작업하다 "이 프로젝트 테스트 포트는 1601로 하자"라고 정한다.
2. 세션이 끝나면 O-Brain가 **자동으로** 그 결정을 '기억(결정 유형)'으로 저장한다.
3. 다음 주, 사용자가 웹 그래프를 열면 그 기억이 **관련 기억들과 연결된 노드**로 보인다 — "8809는 충돌나서 버림"이 빨간 '모순됨' 선으로 이어져 있다.
4. 타임라인을 켜면 포트 결정이 **어떻게 바뀌어 왔는지** 시간순으로 보인다.
5. AI에게도 그 기억이 자동 참고로 제공되어, 같은 설명을 다시 안 해도 된다.

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름
```
AI와 대화(클로드코드) -> 세션 종료 -> O-Brain 자동 추출·보안필터·저장 -> 웹에서 그래프/타임라인으로 탐색 -> 검색
```

### 상세 흐름
1. **자동 캡처**: 클로드코드 훅이 세션 종료 시 대화 내용을 O-Brain에 넘긴다.
2. **추출·정제**: 중요한 기억을 뽑고(유형 분류), 시크릿을 제거한 뒤 SQLite에 저장한다.
3. **연결**: 새 기억을 기존 기억과 관계로 잇는다(Phase 1 기본 연결, Phase 2 자동 추론).
4. **시각화·탐색**: 사용자가 `localhost` 웹에서 **2D/3D 그래프 + 타임라인 + 목록**으로 기억을 탐색한다.
5. **재활용**: AI가 다음 작업에서 관련 기억을 자동 참고한다(필요한 것만 소량 반환해 토큰 절약).

## 6. 안 만드는 것 (Out of Scope — Phase 1 기준)

> 이 목록은 Phase 1에서 만들지 않습니다. AI에게 코드를 시킬 때 함께 공유하세요.

- **로그인·회원가입·계정** — 이유: 내 PC 1인 전용이라 불필요. 보안·복잡도만 늘림.
- **클라우드 동기화·외부 서버 저장** — 이유: "100% 로컬" 핵심 가치 위반. (Revka·Cognee의 관리형 서버/Neo4j 방식 배제)
- **코덱스 정식 자동 연동** — 이유: 코덱스 CLI 훅 성숙도가 클로드코드만 못할 **가능성**(미확인). Phase 1은 클로드코드 확실히, 코덱스는 "되는 만큼". 정식은 Phase 2.
- **기억 자동 정리(중복·모순 병합)** — 이유: 난이도·위험 높음(잘못 합치면 손상). 관계·모순 '표시'는 Phase 1, '자동 정리'는 Phase 3.
- **그래프 분석 알고리즘(중심성·최단경로·blind spot 자동발견)** — 이유: 시각화와 별개로 무거움. Phase 3에서 Cytoscape 보조로.
- **멀티 도구(제미나이·커서 등)** — 이유: 도구마다 연동 방식이 달라 손이 많이 감. Phase 3. **[확인됨, 2026-08-20] 미착수·의도적 보류**(제미나이·커서 실사용 근거 없음 + 연동 스펙 자체가 PRD에 미정의 — 코덱스와 동일 판단 기준. 재개 조건: 실사용 시 재승인, CHECKPOINT 확정)
- **팀 공유·다중 사용자** — 이유: 1인 전용 목적에서 벗어남.

> 참고: 직전 버전에서 "3D 시각화"를 Out of Scope(Phase 3)에 뒀으나, **시각화 핵심 격상 + force-graph 계열(현재 force-graph/3d-force-graph)이 2D·3D를 한 계열 라이브러리로 제공**한다는 근거로 **Phase 1로 이동**했습니다.

## 8. 시각화 사양 (핵심) 🎯

> 회원님 지시: "시각화는 무거워져도 놓칠 수 없는 핵심." → Phase 1부터 제대로 만든다.
> 사양 근거(확인됨): buildautomata 3D viz + TheSethRose Force-Graph-3D + Obsidian/Logseq 그래프뷰.

### 8.1 그래프 뷰 (2D/3D 토글)
- **레이아웃**: force-directed — 연결이 많은 기억끼리 자동으로 군집.
- **2D ↔ 3D 전환**: ~~`react-force-graph`~~ → `force-graph`/`3d-force-graph`(유사 API)로 토글 한 번(2026-08-03 갱신).
- **노드 색**: 분류(온톨로지) 또는 기억 유형(결정/선호/패턴/지식/제약)별.
- **노드 크기**: 중요도(★) + 연결 수 — 중요하고 많이 엮인 기억일수록 큼.
- **글로우(빛남)**: 자주 열어본 기억(access_count) 강조.
- **엣지(선) 스타일**: 관계 종류별 색 — 특히 **`모순됨`은 빨강 점선**, `대체함`은 화살표로 방향 표시.
- **상호작용**: 호버=미리보기 카드, 클릭=상세 패널, 검색어=해당 노드 하이라이트, 카메라 프리셋(3D).

### 8.2 로컬 그래프 vs 글로벌 그래프 (Obsidian 방식)
- **글로벌**: 전체 기억 지도 — 군집·고아(연결 없는) 노드를 한눈에.
- **로컬**: 특정 기억 1개 주변(1~2 hop)만 — 맥락 집중 탐색.

### 8.3 타임라인 뷰
- 기억을 **시간순**으로 배치 — 한 주제의 결정이 어떻게 바뀌었는지(진화) 표시.
- `대체함`/`모순됨`으로 이어진 기억은 타임라인에서 **변천선**으로 연결.
- (Phase 2) **시간여행**: "이 시점에 무엇을 알았나"로 과거 상태 재현.

### 8.4 필터·성능 가드 (무거워도 멈추지 않게)
- **필터**: 분류·기억 유형·중요도·기간·도구(클코/코덱스)별 on/off.
- **성능**: WebGL 렌더(~~react-force-graph~~ → force-graph/3d-force-graph, 2026-08-03 갱신), 노드 수 상한·페이징, 라벨은 줌인 시에만, 무거우면 자동 단순화(엣지 숨김). → "무겁더라도"의 전제 위에서도 **프리징은 방지.**
