1. O-Brain이란?

O-Brain은 AI(Claude Code 등)와 나눈 대화에서 중요한 내용을 자동으로 추출·저장하고, 언제든 꺼내 쓸 수 있게 해주는 완전 로컬 기억 시스템입니다.

쉬운 비유

AI는 매우 똑똑하지만, 대화가 끝나면 모든 것을 잊어버립니다. 마치 기억을 잃는 천재 친구와 대화하는 것과 같습니다.

O-Brain은 그 친구 옆에 두는 자동 메모 노트입니다. "포트는 7740으로 하자", "API 키는 절대 코드에 넣지 말자" 같은 말을 알아서 적어두고, 다음에 다시 알려줍니다.

핵심 특징

기능 설명
100% 로컬 모든 기억이 내 PC(SQLite 데이터베이스)에만 저장됩니다. 외부 서버·클라우드에 아무것도 전송되지 않습니다.
하이브리드 검색 키워드 검색(FTS5)과 의미 유사도 검색(벡터 검색)을 동시에 사용합니다. "비슷한 내용"도 찾아냅니다.
지식 그래프 기억들 사이의 연결을 2D/3D 그래프(점과 선)로 시각화합니다.
시간여행 날짜를 선택해 그 날 기준 "살아있던 기억"만 볼 수 있습니다.
신뢰도 감쇠 AI가 추출한 기억은 시간이 지날수록 신뢰도가 자동으로 낮아집니다 (30일 반감기).
보안 필터 저장 전 API 키·비밀번호·토큰을 자동으로 제거합니다(REDACTED 처리).
자동 백업 서버 시작 시·일괄 삭제 전 자동으로 스냅샷을 저장합니다.
MCP 연동 Claude Code에서 7개의 도구로 기억을 저장·검색·관계 관리합니다.
고아 노드 시각화 사용자 정의 관계가 없는 기억에 점선 테두리를 표시합니다.
일괄 선택·삭제 여러 기억을 한 번에 선택해 삭제하고, 10초 안에 되돌릴 수 있습니다.
⚙ 설정 페이지 목록 개수·그래프 노드 개수·자동 새로고침·테마·안내 배너를 화면에서 직접 조절합니다. 값은 이 브라우저에 저장돼 다음에 열어도 유지됩니다.

4. 설치 방법 (단계별)

O-Brain을 쓰는 방법은 두 가지입니다. 웹 대시보드만 쓸 거라면 4-A, Claude Code에서 자동 기억·슬래시 명령까지 쓰고 싶다면 4-A + 4-B 둘 다 진행하세요.

4-A. 로컬 서버 설치 (필수, 웹 대시보드의 기반)

4-A-1단계: Node.js 설치 (처음 한 번만)

Node.js는 JavaScript(자바스크립트) 프로그램을 실행하는 "엔진"입니다. O-Brain은 JavaScript로 만들어졌기 때문에 이 엔진이 반드시 필요합니다.

  1. 웹 브라우저에서 https://nodejs.org 접속

  2. 초록색 "LTS" 버튼 클릭 (LTS = Long-Term Support, 안정 버전)

  3. 설치 파일 다운로드 후 실행

  4. 설치 화면에서 "Next" → "Next" → "Install" → "Finish" (기본값으로 진행)

  5. 설치 완료 후 터미널(명령 프롬프트)을 새로 열기

    터미널 여는 방법: Windows 키 + R → cmd 입력 → Enter 또는 Windows 키 → "PowerShell" 검색 → 클릭

  6. 아래 명령어 입력해서 버전 확인:

    node --version

    v20.x.x 또는 그 이상이 표시되면 정상입니다.

    npm --version

    숫자(예: 10.x.x)가 표시되면 정상입니다.

4-A-2단계: 의존성 설치

"의존성(Dependency)"이란 O-Brain이 작동하기 위해 필요한 외부 도구 모음입니다. 인터넷에서 자동으로 다운로드됩니다.

  1. 터미널에서 app 폴더로 이동:

    cd D:\AI_Dev_Work\2026y\26y_06m_21d_SoDam_O-Brain\app

    팁: 폴더 경로를 복사해서 붙여넣기 하면 편합니다. 경로에 한글이 있으면 오류가 날 수 있으니 경로를 영문으로 유지하세요.

  2. 의존성 설치 명령어 실행:

    npm install

  3. 완료까지 1~5분 정도 기다립니다. (인터넷 속도에 따라 달라집니다)

  4. 설치 완료 후 오류 메시지 없이 프롬프트가 돌아오면 정상입니다.

    오류가 난다면: 15. 문제 · 오류 대처 방법을 참조하세요.

4-B. Claude Code 플러그인 설치 (선택, MCP·슬래시 명령 쓰려면 필요)

아래 두 줄은 클로드코드 입력칸(프롬프트)에 칩니다. Windows 탐색기가 아니라 클로드코드 안입니다.

① 목록 등록 — 플러그인이 있는 폴더를 알려줍니다.

/plugin marketplace add D:\AI_Dev_Work\2026y\26y_06m_21d_SoDam_O-Brain\plugin

② 설치 — 그 목록에서 O-Brain을 깝니다.

/plugin install o-brain@o-brain-local

③ 클로드코드 재시작 → 설치 완료.

  • o-brain = 플러그인 이름, o-brain-local = 목록(마켓플레이스) 이름.
  • 한 번에 /plugin install <폴더경로> 로 하면 "Marketplace not found" 오류가 납니다. 꼭 2단계로 하세요.
  • "git 저장소가 아니다"라고 막히면, 그 plugin 폴더에서 git init && git add -A && git commit -m init 후 다시 ①.

잘 깔렸는지 확인: 클로드코드 입력칸에 /o-brain:status(기억 수·상태 확인) 또는 /o-brain:selftest(✅✅✅ 이면 정상)를 입력해 보세요.

7-1. 화면 구성 (상단 탭)

탭 설명
그래프 기억들을 점과 선으로 표시하는 지식 맵. 첫 화면.
개요 전체 현황: 총 기억 수, 유형별·카테고리별 분포, 연결 많은 기억
목록 기억을 카드 형태로 나열. 스크롤로 탐색. 선택 모드로 일괄 삭제 가능
타임라인 시간순으로 기억 표시
⚙ 설정 목록·그래프·새로고침·화면·안내 5개 설정을 이 화면에서 직접 조절 (7-12절 참고)

빠른 검색·이동: 어디서든 ⌘K(맥) / Ctrl+K(윈도우) 를 누르면 작은 검색창이 떠서 명령(보기 전환·테마·내보내기)·기억 을 한 번에 찾아 바로 이동할 수 있어요.

7-2. 그래프 탭 사용법

그래프란? 기억들이 점(노드)으로 표시되고, 비슷하거나 연관된 기억끼리 선(엣지)으로 연결됩니다.

  • 마우스를 점 위에 올리면: 연결된 기억들이 강조됩니다
  • 점을 클릭하면: 오른쪽에 상세 정보가 열립니다
  • 검색창: 위쪽 검색창에서 검색하면 해당 점이 밝아집니다
  • 2D/3D 전환: 상단의 "2D"/"3D" 버튼으로 전환
  • 확대/축소: 마우스 휠 또는 우하단 버튼
  • 점선 테두리: 사용자 정의 관계가 없는 "고아 기억"에 표시됩니다
  • 기억이 많아지면: 그래프는 가장 중요한 것 위주로 보여주고 "전체 N개 중 상위 M개"라고 알려줍니다(느려지지 않도록). 몇 개를 보여줄지는 ⚙ 설정에서 조절할 수 있습니다(7-12절).

색상 의미:

  • 점 크기 = 중요도 + 연결 수 (클수록 중요)
  • "분류색" 버튼: 유형별/카테고리별로 색상 변경

7-3. 기억 상세 보기

목록이나 그래프에서 기억을 클릭하면 오른쪽에 상세 패널이 열립니다:

  • 내용: 저장된 기억 텍스트
  • 유형: 지식/결정/약속/금지 등
  • 중요도: ★ 별점 (1~5)
  • 신뢰도: 0.1~1.0 (AI 추출 기억은 시간이 지나면 자동으로 낮아짐)
  • 카테고리: 자동 분류된 주제
  • 생성일: 기억이 저장된 날짜
  • 저장 세션: 어느 대화 세션에서 저장됐는지 (여러 Claude Code 창을 동시에 쓸 때 출처 구분에 유용)
  • 조회수: 이 기억을 열어본 횟수 (많이 볼수록 그래프에서 더 빛남)

7-4. 기억 편집 및 삭제

상세 패널에서:

  • 편집(✏️): 내용, 유형, 중요도 수정 가능. 편집 시 비밀 정보 자동 제거 재실행.
  • 삭제: 해당 기억을 영구 삭제. 삭제 전 자동 백업 권장.
  • 복사: 내용을 클립보드에 복사

7-5. 기억 추가 (UI에서 직접)

상단 "+" 버튼 또는 API로 기억을 직접 추가할 수 있습니다:

  • 내용 입력
  • 유형 선택 (지식/결정/약속 등)
  • 중요도 선택 (1~5)
  • 저장 클릭 → 자동으로 의미 분석 및 임베딩 생성

7-6. 기억 관계 연결

기억 상세 패널 하단 "관계" 섹션에서:

  1. "관계 추가" 클릭
  2. 연결할 다른 기억 ID 입력 — "관련 있을 만한 기억"이 자동 추천되니 대상을 일일이 찾을 필요는 없습니다
  3. 관계 유형 선택: SUPERSEDES(번복), SUPPORTS(뒷받침), INFLUENCES(영향), CONTRADICTS(충돌) — 종류는 사람이 직접 확정합니다(자동 판정하지 않음)
  4. 저장

SUPERSEDES 선택 시: 자동으로 대상 기억의 유효 종료일(valid_until)이 오늘로 설정됩니다. (해당 기억이 이 새 기억에 의해 "무효화"되었다는 의미)

7-7. 검색

상단 검색창에서:

  • 하이브리드 검색: 키워드 + 의미 유사도를 동시에 검색
  • 예시: "포트 설정" 검색 → "포트"가 포함된 기억과 비슷한 내용의 기억 모두 표시
  • 검색 결과가 서버 쪽 상한으로 잘렸을 경우 "관련 기억이 N건 더 있어요" 안내가 함께 표시됩니다(결과가 조용히 사라지지 않도록).

7-8. 필터 · 정렬

상단 필터바에서:

  • 범위(scope): 전체(global) / 프로젝트(project) 구분
  • 정렬: 최신순 / 오래된순 / 중요도순
  • 중요도·기간·프로젝트 필터: 프로젝트는 최근 활동순으로 표시됩니다

프로젝트 자동 분류: 기억은 그 세션에서 실제로 편집한 파일이 속한 프로젝트로 자동 분류됩니다. Claude Code를 어디서 켰든, 가장 많이 만진 프로젝트로 들어갑니다.

7-9. 시간여행 기능

날짜 입력창에서 과거 날짜를 선택하면:

  • 그 날짜 기준으로 "살아있던 기억"만 표시됩니다
  • SUPERSEDES로 무효화된 기억은 무효화 날짜 이후에는 표시되지 않습니다
  • 기억 변천 과정을 추적할 때 유용합니다

예시: 2026-06-01을 선택하면 그 날짜까지 유효했던 기억만 볼 수 있습니다.

7-10. 내보내기

상단 우측 "내보내기" 버튼:

  • JSON 형식: 프로그램이 읽을 수 있는 데이터 형식
  • 마크다운 형식: 텍스트 편집기에서 읽기 좋은 형식

7-11. 일괄 삭제

목록 탭에서 "선택" 버튼을 누르면 여러 기억을 한 번에 선택해서 삭제할 수 있습니다.

  1. "선택" 클릭 → 체크할 수 있는 모드로 전환
  2. 지울 기억들 선택 → 하단(또는 상단) 툴바에 "N개 선택됨"과 "삭제" 버튼 표시
  3. "삭제" 클릭 → 확인 창에서 "삭제" 재확인(자동 백업이 먼저 저장됩니다)
  4. 삭제 직후 화면 하단에 "N개 삭제됨 · 되돌리기" 토스트가 뜨고, 10초 안에 "되돌리기"를 누르면 복원됩니다(단, 새 번호(id)로 다시 저장되며, 연결돼 있던 관계는 최선을 다해 복원하되 100% 보장은 아닙니다)

주의: 10초가 지나면 되돌리기 버튼이 사라집니다. 그 후 복구하려면 app/data/backup/ 폴더의 최신 백업 파일을 사용하세요.

7-12. ⚙ 설정 페이지

헤더의 톱니바퀴(⚙) 아이콘을 누르면 전용 설정 페이지로 이동합니다(그래프/개요/목록/타임라인과 같은 급의 5번째 화면). 총 5개 항목을 조절할 수 있고, 전부 이 브라우저에 저장돼 다음에 열어도 값이 유지됩니다.

그룹 항목 설명
목록 한 번에 불러올 개수 목록·타임라인·개요에 한 번에 불러올 기억 개수(50/100/200/500/직접입력 1~500). 그래프 탭에는 적용되지 않습니다.
그래프 표시할 노드 개수 그래프 탭에 표시할 노드 상한(300/600/1000/2000/직접입력 50~2000). 목록 개수와는 별개입니다.
새로고침 자동 새로고침 켜기 켜두면 일정 주기(기본 45초, 10~300초 조절 가능)로 새 기억이 있는지 조용히 확인해 화면에 반영합니다.
화면 테마 밝게/어둡게 전환. 헤더의 해/달 아이콘 버튼과 동일한 설정을 공유합니다.
안내 안내 배너 표시 상단의 "클로드코드 대화에서 자동으로 모은 기억이에요" 안내문을 다시 보이거나 숨깁니다.

각 드롭다운에서 "직접 입력…"을 고르면 숫자 입력칸이 나타납니다. 범위를 벗어난 값(예: 그래프 노드에 99999)이나 소수점 값을 넣어도 서버·화면 양쪽에서 안전한 값으로 자동 보정됩니다.

7-13. 중복 기억 정리

개요 탭 하단에 "중복 후보"가 발견되면 카드로 표시됩니다(비슷한 내용의 기억이 있을 때만 나타남).

  1. 후보 목록 확인: 개요 탭을 열면 자동으로 비슷한 기억 쌍을 찾아 보여줍니다.
  2. 카드 클릭: 후보 카드를 누르면 두 기억의 전체 내용을 나란히 비교하는 확인창이 뜹니다.
  3. 정리 방법 선택:
    • A만 남기기: 위쪽 기억만 남기고 아래쪽 삭제
    • B만 남기기: 아래쪽 기억만 남기고 위쪽 삭제
    • 둘 다 이어붙이기: 두 내용을 한 기억으로 합치고 나머지 하나는 삭제
    • 취소: 아무것도 안 하고 닫기
  4. 안전장치: 실행 전 자동으로 백업이 만들어지고, 실행 직후 10초 안에 화면에 뜨는 "되돌리기"를 누르면 원래대로 복원됩니다(합치기였다면 원래 내용으로, 삭제였다면 삭제된 기억이 새 번호로 다시 생성됩니다).
  5. 기억이 1500건을 넘으면 안전을 위해 이 기능이 자동으로 비활성화됩니다("기억이 많아 건너뜀" 문구가 표시됨).

비교 기준이 검색과 다릅니다. 검색은 "관련 있어 보이면" 걸리도록 느슨하게 잡혀 있지만, 중복 정리는 "정말 같은 내용에 가까운 경우"만 후보로 올라오도록 훨씬 엄격하게 잡혀 있습니다. 그래서 검색에서는 여러 건이 나와도 중복 후보에는 안 뜰 수 있습니다 — 정상입니다.

8. 사용 방법 — MCP 도구 · Claude Code 플러그인

8-1. MCP 서버 등록 (settings.json 방식)

**MCP(Model Context Protocol)**는 Claude Code가 외부 도구를 사용할 수 있게 해주는 규격입니다. Claude Code의 설정 파일(~/.claude/settings.json)에 아래 내용 추가:

{
  "mcpServers": {
    "o-brain": {
      "command": "node",
      "args": ["C:/절대경로/app/src/mcp-server.mjs"]
    }
  }
}

절대 경로 예시: C:/Users/내이름/obrain/app/src/mcp-server.mjs 경로에 백슬래시(\) 대신 슬래시(/)를 사용하세요.

등록 후 Claude Code를 재시작합니다.

8-2. MCP 도구 목록

도구 이름 하는 일 사용 예
save_memory 기억 저장 "이 결정을 기억해줘"
search_memory 키워드/의미로 검색 "포트 설정 관련 기억 찾아줘"
get_memory 특정 ID의 기억 조회 기억 ID로 상세 정보 확인
get_related 연관 기억 목록 이 기억과 관련된 것들
get_timeline 시간순 기억 목록 최근 기억들 보기
add_relation 두 기억 사이 관계 추가 "A가 B를 번복했다고 연결해줘"
list_categories 카테고리별 기억 수 어떤 주제가 많은지 확인

8-3. Claude Code에서 사용 예시

나: "방금 포트 7740으로 결정했어. 기억해줘."
Claude: (save_memory 도구 실행) "포트 7740 결정을 기억에 저장했습니다."

나: "이전에 포트 관련 결정 뭐 했었지?"
Claude: (search_memory 도구 실행) "저장된 기억 중 포트 관련: ..."

8-4. Claude Code 플러그인 슬래시 명령 (4-B에서 설치했다면)

명령 하는 일
/o-brain:status 쌓인 기억 수·최근 기억·상태를 한국어로 보여줌
/o-brain:selftest 두뇌(저장·보안가림·검색)를 한 방에 점검. ✅✅✅ 면 정상
/o-brain:remember 이번 대화의 결정만 골라 저장(설치된 Claude Code/Codex가 직접 처리 — 별도 API 키·비용 없음)
/o-brain:link 관련 기억을 제안 → 관계 종류는 직접 확정
/o-brain:backup 수동 백업 생성
/o-brain:open 대시보드를 브라우저로 열기(서버가 꺼져 있으면 자동으로 켬)

작동 원리 한 줄: 대화를 끝낼 때(/clear), O-Brain이 그 대화를 훑어 "결정/약속/금지" 문장만 골라 자동 저장합니다. 잡담이나 단순 명령(cd 폴더 등)은 잡히지 않습니다.

9. 작동 방법 (내부 구조)

이 섹션은 "어떻게 작동하는지"가 궁금한 분을 위한 설명입니다. 기술적 세부 내용이므로 관심 없으면 건너뛰어도 됩니다.

9-1. 기억 저장 과정

  1. 입력: MCP 도구나 웹 UI에서 텍스트 입력
  2. 보안 필터: API 키·비밀번호 등 민감 정보 자동 제거
  3. 중복 확인: 이미 있는 기억과 비교해 중복이면 건너뜀
  4. 임베딩: 텍스트를 384차원 숫자 벡터로 변환 (all-MiniLM-L6-v2 모델, 로컬 실행)
  5. 저장: SQLite 데이터베이스에 저장 (텍스트 + 벡터 + 메타데이터)
  6. 카테고리 분류: 규칙 기반으로 주제 자동 분류

9-2. 검색 과정 (하이브리드 검색)

  1. 키워드 검색(FTS5): 정확한 단어 매칭
  2. 벡터 검색: 의미적으로 유사한 내용 검색
  3. RRF 병합: 두 검색 결과를 합쳐 최종 순위 결정 (C=60 상수 사용)
  4. 결과 반환: 상위 결과를 관련도 순으로 반환. 서버 상한으로 잘린 경우 "더 있어요" 안내 포함

9-3. 신뢰도 감쇠 (Confidence Decay)

AI가 추출한 기억은 시간이 지날수록 신뢰도가 자동으로 낮아집니다:

  • 공식: 새 신뢰도 = 이전 신뢰도 × 0.5^(경과일수/30)
  • 의미: 30일이 지나면 신뢰도가 절반으로, 60일이면 1/4로 낮아짐
  • 예외: 사용자가 직접 입력한 기억(source='user')과 신뢰도 0.99 이상은 감쇠 안 됨
  • 최솟값: 0.1 미만으로는 내려가지 않음
  • 주기: 서버 시작 시 마지막 적용 후 12시간 이상 지난 경우 실행(최초 실행 시에는 시각만 기록하고 건너뜀 — 예전에는 이 처리가 없어 첫 실행 때 기존 기억이 즉시 바닥까지 떨어지는 버그가 있었으나 수정됨)

9-4. 그래프 구성

  • 노드: 각 기억이 하나의 점
  • 엣지(자동): 임베딩이 비슷한 기억끼리 자동으로 연결 (sqlite-vec KNN)
  • 엣지(수동): 사용자가 직접 추가한 관계 (SUPERSEDES/SUPPORTS 등) — 색깔 선으로 표시
  • 크기: 중요도 + 연결 수에 비례
  • 성능 제한: 기본 최대 600개 노드만 표시(중요도 높은 것 우선). ⚙ 설정에서 50~2000 사이로 조절 가능(7-12절)
  • 성능 가드(자동 단순화): 전체 기억이 1500건을 넘으면 노드마다 유사도를 계산하는 무거운 연산을 자동으로 건너뛰고, 저장된 관계(수동 연결)만으로 그래프를 그립니다. 화면이 멈추는 것을 막기 위한 자동 전환이며, 기억 수에 따라 자동으로 켜지고 꺼집니다.

9-5. 중복 기억 찾기·정리 로직

  • 탐지 기준: 벡터 검색 거리값(distance)이 0.6 이하인 기억 쌍을 "중복 후보"로 봅니다. 이 값은 코사인 유사도가 아니라 "낮을수록 비슷함"을 뜻하는 원시 거리값으로, 실측상 완전히 같은 내용은 0에 가깝고 검색에 걸릴 정도로만 관련 있는 내용은 1에 가깝습니다 — 그래서 "찾기"보다 훨씬 엄격한 기준(0.6)을 씁니다.
  • 자동 실행 없음: 후보를 찾아서 화면(개요 탭)에 보여줄 뿐, 자동으로 지우거나 합치지 않습니다. 반드시 사람이 화면에서 두 내용을 눈으로 비교한 뒤 버튼을 눌러야 실행됩니다.
  • 정리 방법 3가지: "A만 남기기"(B 삭제), "B만 남기기"(A 삭제), "둘 다 이어붙이기"(두 내용을 합쳐 하나로 저장하고 나머지 삭제).
  • 안전장치: 실행 전 자동 백업 생성, 실행 후 10초 안에 "되돌리기"로 원상복구 가능(자세한 사용법은 7-13절).
  • 규모 제한: 기억이 1500건을 넘으면 안전을 위해 중복 탐지 자체를 건너뜁니다("기억이 많아 건너뜀" 안내 표시).

9-6. 로컬 API 토큰

서버가 시작될 때마다 새로운 임의 토큰을 생성합니다:

  • 브라우저에 자동으로 주입되어 API 요청 시 함께 전송
  • data/.api-token 파일에도 저장 (MCP 서버용)
  • 서버 재시작 시 새 토큰 발급 (보안 강화)
  • 모든 /api/ 요청은 서버가 이 토큰을 실제로 검사합니다. 토큰이 없거나 다르면 403(허용되지 않은 요청)으로 거부됩니다 — 브라우저 화면은 자동으로 토큰을 붙여 보내므로 정상 사용 중엔 신경 쓸 필요가 없습니다.

9-7. ⚙ 설정값 저장 방식

⚙ 설정 페이지의 값들(개수·그래프 노드 수·자동 새로고침·테마·안내 배너)은 서버가 아니라 이 브라우저의 localStorage에 저장됩니다. 즉:

  • 다른 컴퓨터·다른 브라우저에서 열면 기본값(100개/600노드/45초/어둡게/안내 표시)부터 다시 시작합니다
  • 브라우저 데이터(쿠키·사이트 데이터)를 지우면 이 설정값도 함께 초기화됩니다
  • 서버로 전송되거나 다른 사람과 공유되지 않습니다(순전히 이 화면 전용 UI 취향)

12-1. 핵심 보안 원칙

O-Brain은 "Secure by Design" 원칙을 따릅니다: 기능보다 먼저 안전, 기본 설정이 가장 안전한 상태.

12-2. 네트워크 보안

항목 설명
바인딩 주소 127.0.0.1 (내 PC 전용). 0.0.0.0(모든 기기)으로 절대 열리지 않음
CORS 정책 localhost 또는 127.0.0.1에서 온 요청만 허용. 다른 사이트 요청 거부(403)

서버가 자동으로 적용하는 HTTP 보안 헤더:

헤더 값 의미

Referrer-Policy no-referrer 참조 URL 전송 안 함

12-4. 데이터 보안

항목 처리 방법
API 키 감지 sk-, AKIA, Bearer 등 패턴 → [REDACTED]로 자동 치환
비밀번호 password=, secret= 등 → 자동 제거
저장 전 검사 모든 content 필드는 redact.mjs를 통해 저장
편집 시 재검사 내용 수정 시에도 자동 재필터링

12-5. 입력값 검증 (실측 확인)

시도한 입력 서버 반응
음수 limit/offset 최솟값(1 또는 0)으로 자동 보정
비숫자 limit(abc) 기본값으로 자동 대체
범위를 벗어난 큰 값 최댓값으로 클램프(예: 그래프는 2000, 목록은 500)
소수점 값(예: 500.7) 정수로 반올림 처리(과거엔 서버 오류가 났던 부분, 수정됨)
중요도(1~5)에 범위 밖 숫자(예: 999, -5) 1~5 사이로 자동 보정
신뢰도(0~1)에 범위 밖 숫자나 문자 0~1 사이로 자동 보정, 숫자가 아니면 기본값 사용
존재하지 않는 기억 id 404 반환
잘못된 형식의 id(문자 등) 400 반환
허용 안 된 출처(Origin)의 요청 403 반환
API 토큰 없음·틀림 403 반환(9-6절)
SQL 특수문자가 섞인 검색어 파라미터 바인딩으로 안전 처리, 정상적으로 빈 결과 또는 정상 결과 반환
화면에 스크립트 코드(<script>)가 담긴 내용 저장 그대로 텍스트로 저장되지만, 화면에 표시될 때는 글자 그대로만 보이고 실행되지 않음(실제 브라우저로 확인됨)

16. FAQ (자주 묻는 질문)

Q. 데이터는 어디에 저장되나요?

A. 모든 기억은 app/data/obrain.db (SQLite 파일)에 저장됩니다. 이 파일은 내 컴퓨터 안에만 있으며, 외부로 전송되지 않습니다.

Q. 인터넷이 필요한가요?

A. 최초 설치 시(npm install)와 임베딩 모델 첫 다운로드 시에만 필요합니다. 이후에는 완전히 오프라인으로 동작합니다.

Q. Claude Code 없이 사용할 수 있나요?

A. 네. 웹 대시보드(http://127.0.0.1:7740)만으로도 기억 추가·검색·관계 관리를 모두 할 수 있습니다. Claude Code는 MCP 도구·플러그인 연동 시에만 필요합니다.

Q. 비용이 드나요?

A. O-Brain 자체는 무료입니다. Claude Code나 Anthropic API를 사용하는 경우 해당 서비스의 요금이 적용될 수 있습니다. AI 추출(/o-brain:remember)도 설치된 호스트 LLM을 그대로 활용하므로 별도 API 키·과금이 없습니다.

Q. 기억이 실수로 삭제됐어요. 복구할 수 있나요?

A. 일괄 삭제 직후라면 화면의 "되돌리기"를 10초 안에 누르세요(자동 백업도 삭제 전 생성됩니다). 시간이 지났다면 app/data/backup/ 폴더의 최신 .db 파일로 복원할 수 있습니다. (단건 삭제 전 백업은 자동 생성되지 않으므로 중요 기억은 정기적으로 npm run backup 실행 권장)

Q. 포트를 변경할 수 있나요?

A. 네. app/.env.local 파일에 OBRAIN_PORT=7741 추가 후 서버 재시작하면 됩니다.

Q. 여러 프로젝트를 구분해서 관리할 수 있나요?

A. 기억 저장 시 scope=project와 project 이름을 지정하면 프로젝트별로 분류됩니다. Claude Code로 저장한 기억은 그 세션에서 실제로 편집한 파일의 프로젝트로 자동 분류됩니다. 검색 및 목록 조회 시 scope 필터로 특정 프로젝트 기억만 볼 수 있습니다.

Q. Mac이나 Linux에서도 동작하나요?

A. Windows 기준으로 개발되었습니다. macOS·Linux에서는 기본적으로 동작하지만 better-sqlite3 네이티브 모듈 빌드에서 오류가 날 수 있습니다. 오류 시 npm install --force 또는 Node.js LTS 재설치를 시도해 보세요.

Q. 신뢰도가 계속 낮아지는데 어떻게 해야 하나요?

A. 신뢰도 감쇠는 AI가 추출한 기억에만 적용됩니다. 직접 입력(source=user)하거나 신뢰도를 0.99 이상으로 설정하면 감쇠가 적용되지 않습니다. 중요한 기억은 웹 UI에서 직접 편집해 내용을 확인하거나 신뢰도를 높일 수 있습니다.

Q. "고아 기억(점선 테두리)"이란 무엇인가요?

A. 사용자가 직접 추가한 관계(SUPERSEDES, SUPPORTS 등)가 없는 기억입니다. 자동으로 계산된 유사도 연결선은 있을 수 있지만, 명시적인 관계가 없다는 의미입니다. 점선 테두리 기억들을 확인하고 관계를 추가하면 지식 그래프가 더 풍부해집니다.

Q. 시간여행 기능은 어떻게 사용하나요?

A. 웹 대시보드 상단의 날짜 입력 필드에서 날짜를 선택하면, 그 날짜 기준 "살아있던" 기억만 표시됩니다. SUPERSEDES로 무효화된 기억은 무효화 날짜 이후 표시되지 않습니다. 날짜를 비우면 현재 상태(기본값)로 돌아옵니다.

Q. 그래프 탭 노드 개수와 목록 개수 설정은 같은 건가요?

A. 아닙니다. ⚙ 설정 페이지의 "한 번에 불러올 개수"는 목록·타임라인·개요에만 적용되고, "표시할 노드 개수"는 그래프 탭에만 따로 적용됩니다. 하나를 바꿔도 다른 하나는 그대로입니다.

Q. ⚙ 설정에서 바꾼 값은 어디에 저장되나요? 다른 사람과 공유되나요?

A. 이 브라우저의 localStorage에만 저장됩니다. 서버나 DB로 전송되지 않고, 다른 컴퓨터·브라우저와 공유되지도 않습니다.
